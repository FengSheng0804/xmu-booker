# Android 独立版使用与构建

维护作者：Codex；更新日期：2026-11-13（Asia/Shanghai）；轮次：R71。文档类型：公开使用说明；验证状态：正式APK本地构建和签名校验通过，GitHub新流水线需配置签名Secrets并提交后验证；其余检查见对应轮次报告。

## 安装与授权

支持 Android 11 及以上设备，按校区同步学校场馆；通过学校接口校验后显示实际时段，预约仍受学校当前规则限制。

下载安装 Release 中的 ARM64 APK。首次启动无需项目账号或服务器地址，进入“获取或更新本机授权”，按页面说明完成本机无线调试配对和微信 XWeb 调试设置，再进入本人体育预约页面。此操作只用于获取和校验本人的学校授权，不读取聊天内容。无线调试连接地址固定为本机，填写的端口不能用于连接其他设备。

无线调试配对成功后，还需在微信内部打开 `http://debugxweb.qq.com/?inspector=true`，再重新进入学校体育页面。App提供复制入口和检测按钮，未检测到微信页面调试时不能读取授权，无需为此重新配对。入口原理可参考[原始技术记录](https://github.com/5ec1cff/my-notes/blob/master/xweb-debugging.md)，不同微信版本可能改变行为。

已有同包名、同签名的正式版可直接升级，并尝试保留 Android Keystore 中的学校授权。卸载、清除应用数据或使用不同签名安装不能保留原授权；失效时需重新获取。独立版不会连接旧服务器导入计划，需要重新创建计划。

## 计划和后台运行

1. 完成本机授权后同步学校场馆，按所选入场日期查询实际时段和余量。
2. 选择“定时执行”创建单次/每周计划，或选择“监控余量”监控单个入场日期的候选时段。候选顺序即优先级。
3. 核对学校当前放号时间、提前天数和有效执行窗口。页面的历史默认值不代表学校当前规则；确认后才能启用计划。
4. 在系统设置允许通知、精确闹钟、不受电池优化限制及后台运行。华为/荣耀请允许自启动、关联启动、后台活动，可锁定最近任务。有任务时自动显示后台守护通知；定时任务空闲等待时不持续持锁，执行或正在监控时维持 CPU 运行。
5. 计划保存后默认启用，无需额外打开总开关。可从计划菜单暂停。

计划、任务和执行记录都在手机本地。重启后系统允许时恢复定时安排；系统强制停止App后需重新打开。Android省电策略、锁屏网络、权限撤回和断网都会影响执行，不保证手机关机、强制停止或授权失效后的预约。

监控模式可选择学校已返回的满员或未开放时段，设置开始、截止及检查间隔（可选10秒，默认30秒）。默认监控一小时，可配置至多72小时；发现空位后核对本人订单并重新检查余量，再尝试预约。成功、截止或暂停后停止。网络问题会退避重查，提交结果不明时只查单，不自动重发。监控会增加耗电和网络使用；间隔还受请求耗时及系统调度影响。

同步场馆和订单时，对独立的只读请求分批并行处理；同一短期授权会话内复用场馆信息及已校验的订单归属，余量与二维码详情仍实时读取。首页“本地消息”固定高度，可在区域内滚动查看更多，每次增加10条；订单中的入场二维码可点击全屏查看，点击左上角关闭按钮返回，全屏不显示标题。

移除最近任务或进程退出后通过独立报警、前台服务和持久化作业恢复。尚未提交的领取状态可以恢复；已经提交的状态只核对学校订单。厂商清理器若额外冻结 App，仍需允许系统后台与启动权限。

任务详情可以在准备/执行窗口内运行任务。提交结果未知时，该入口只核对学校订单，不会再次提交；界面会保留需要人工核对的状态。暂停、删除计划和清除本地数据不会取消已经生成的学校订单。

学校订单为本人订单的本机缓存，需同步取得当前状态。点击订单可向学校读取有效入场二维码，仅在订单详情显示。取消预约及学校自身的缴费操作请前往学校原入口，本App不提供学校订单取消或付款接口。

连续同步操作会在内存中短暂复用已验证的只读学校会话，最长 60 秒，不缓存二维码或实时余量。更换或删除授权后不再复用原会话。获取单个订单入场码找到该本人订单后即可读取详情；预约前和结果核对仍完整查单，真实预约仍重新校验身份。

## 从源码构建

需要 Flutter 3.47.8、JDK17、Android SDK以及网络获取依赖。CI使用相同Flutter版本，所有业务测试使用合成响应，不访问学校。

```sh
cd apps/mobile
flutter pub get
flutter analyze
flutter test
flutter build apk --profile --flavor production --target-platform android-arm64 --split-per-abi
cd android
./gradlew :app:testProductionDebugUnitTest
```

调试与 profile 包使用 `.debug` 包名和同一调试签名，可保留数据覆盖升级，与正式版分开。Windows 用户直接运行 `scripts/build-mobile.ps1` 默认构建体积更小的 AOT profile 包；需要热重载时显式使用 `-Mode debug`。

正式版需要设置环境变量 `XMU_ANDROID_KEY_PROPERTIES`，指向仓库外的签名属性文件，包含 `storeFile`、`storePassword`、`keyAlias`、`keyPassword`，再运行 `scripts/build-mobile.ps1 -Mode release`。使用自己的密钥构建的包无法覆盖其他签名的正式包；不要把密钥或属性文件提交到Git。

### GitHub生成正式APK

GitHub Actions对所有提交运行源码和设备测试；主分支检查全部通过后，`release-apk`任务使用正式签名构建Release版，不再上传调试APK。下载运行结果Artifacts中的`xmu-booker-arm64-release`，解压得到`xmu-booker-arm64-release.apk`及`SHA256SUMS`，产物保留90天。此配置保存Actions构建产物，不会自动发布GitHub Release。

首次使用需在仓库Settings → Secrets and variables → Actions → New repository secret添加下列四项：[GitHub官方说明](https://docs.github.com/en/actions/how-tos/write-workflows/choose-what-workflows-do/use-secrets)。

| Secret名称 | 内容 |
| --- | --- |
| `XMU_ANDROID_KEYSTORE_BASE64` | 正式签名keystore的单行Base64内容 |
| `XMU_ANDROID_STORE_PASSWORD` | keystore密码 |
| `XMU_ANDROID_KEY_ALIAS` | 正式签名密钥别名 |
| `XMU_ANDROID_KEY_PASSWORD` | 该密钥密码 |

保持使用同一正式签名以便后续覆盖更新。Secrets不放进源码、issue或聊天；Base64只是编码。构建中仅在runner临时目录还原签名文件，结束后清理；缺失Secrets时明确失败，不回退调试签名。Pull Request不运行带密钥的正式构建。可在Actions中手动选择main运行工作流。

正式版包名没有`.debug`，与测试版分开存储；从测试版转用正式版需要在正式版内重新获取授权、设置计划，原测试版计划请按需要暂停。

## 数据和问题报告

“本机设置”可暂停执行并清除本地授权、计划、记录、缓存和消息。操作不会删除学校已有预约。

“清理临时文件”仅移除旧版调试资源和私有诊断临时文件，保留授权与预约数据。AOT 安装包首次启动也会执行该清理。

提交问题时提供系统版本、App版本、操作步骤和界面错误码；请勿上传学号、学校授权、二维码、Cookie、原始订单响应或含个人数据的截图。详见[隐私说明](PRIVACY.md)及[第三方声明](THIRD_PARTY.md)。
